Deep-Ensemble CLV

Explainable Gradient Boosting with Entity Embeddings for Customer Lifetime Value Prediction

Research project: entity embeddings for high-cardinality categorical features, fed into a gradient boosting model, explained end-to-end with SHAP (traced back through embedding dimensions to original categories).

Setup
bash
pip install -r requirements.txt
Pipeline stages
Stage	Script	Status
1	src/data_cleaning.py	Cleans raw data, handles noise/missingness
2	src/feature_engineering.py	RFM + behavioral features, leakage-safe
3	src/embedding_model.py	Trains entity embeddings for categorical vars
4	src/train_gbm.py	Gradient boosting on embeddings + engineered features
5	src/explain_shap.py	SHAP explanations mapped back to categories

Run stages in order:

bash
python src/data_cleaning.py
python src/feature_engineering.py   # coming next
python src/embedding_model.py       # coming next
python src/train_gbm.py             # coming next
python src/explain_shap.py          # coming next
Data
data/raw/ — original synthetic customers.csv and transactions.csv (15,000 customers, ~63,000 transactions, intentional noise for realistic cleaning)
data/processed/ — cleaned outputs, generated by src/data_cleaning.py
Known data-quality handling decisions
total_orders is excluded from model features (leakage risk — correlates ~0.97 with actual transaction count).
churned_flag has ~3% label noise that is documented, not corrected (cannot be un-flipped without ground truth).
review_score missingness is kept as an explicit flag rather than imputed.
